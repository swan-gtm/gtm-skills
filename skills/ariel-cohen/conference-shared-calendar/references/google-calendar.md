# Google Calendar reference

Checked 2026-09-23. Labels and organizational permissions can change; inspect the current UI.

Create a dedicated calendar from Calendar's desktop settings, name it, and set its timezone. In its sharing settings, add the intended people with the requested view/edit rights. Work or school policies can restrict sharing. Do not make a team calendar public merely to make its link easier to share. See [Google's sharing guide](https://support.google.com/a/users/answer/11617205?hl=en) and [permission definitions](https://support.google.com/calendar/answer/15716974?hl=en-GB).

For a file import, open Settings → Import & export, select the ICS and explicitly select the destination calendar before importing. Verify the destination rather than accepting the primary-calendar default. An import does not stay synchronized with its source. See [Google's import instructions](https://support.google.com/calendar/answer/37118?hl=en-uk).

Use an existing accepted personal invitation as the real commitment when available. A separate reference copy belongs on the shared calendar as Free. Color coding can help navigation but cannot make an event blocking or nonblocking.

For maintenance, keep local source IDs and remote calendar IDs. First compare source changes with existing events. Update only mapped events and report additions, revisions, cancellations, and unresolved matches separately. Do not silently delete unmapped events. Cancellation handling should preserve enough information to explain the change to calendar users.
