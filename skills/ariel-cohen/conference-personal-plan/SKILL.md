# Personal conference plan

Turn a reference agenda into actual commitments without blocking everyone for every session. Use `assets/personal-plan-worksheet.md`.

## Gather and reconcile

Read the supplied agenda, existing personal calendar when accessible, confirmed invitations, selected sessions and assigned duties. Establish dates, venue timezone, priorities, travel constraints, and whose calendar may be edited. Check source timestamps and distinguish confirmed attendance from an interesting option. An entry on the shared agenda does not prove the user will attend.

Reuse original accepted invitations for dinners and meetings. Do not create duplicate personal copies of an existing commitment. If a tentative placeholder conflicts with a confirmed organizer update, propose updating the mapped placeholder and preserve the source trail. Unknown session times remain unresolved; do not invent blocks.

## Make the plan

1. Protect existing meetings, speaking slots, assigned booth shifts, travel, and other confirmed commitments first.
2. Choose among simultaneous sessions using the user's stated interests and priorities. Explain meaningful tradeoffs; keep unresolved choices as options until selected.
3. Add realistic walking, arrival, meals and travel allowances based on locations and user preferences. Label estimates. Leave explicit meeting/networking windows.
4. For a team, map each duty to the actual person, with start/end, location and backup if supplied. Report uncovered intervals and overlaps. Do not assign a new duty to someone merely because their calendar looks free.
5. Keep the shared full agenda Free. Put chosen commitments and agreed duty blocks on only the relevant person's personal conflict-checking calendar as Busy, within the authorized editing scope. If the existing task only asks for a plan, deliver the plan before making live changes.
6. Avoid an all-day Busy conference block when the purpose is only to record attendance. Do not change existing Busy events without understanding their purpose and having authorization.

## Check and deliver

Check timezone conversion, overlaps, sufficient transfer time, meal breaks, duty coverage and retained booking windows. With live access, verify the final personal calendar entries and that Cal.com reflects them when that tool is available. With no access, deliver a table or importable personal itinerary and explicitly list the checks still needed.

Return a day-by-day plan with times/timezone, locations, commitment versus optional status, and sources; a list of unresolved choices; and any uncovered duties. Record which live events were created or updated and their IDs privately to avoid duplicates on reruns. Do not RSVP, invite teammates, or send meeting requests unless the user has authorized those actions. Suggest conference-booking-links for testing public meeting availability if installed; this skill must also work independently.
