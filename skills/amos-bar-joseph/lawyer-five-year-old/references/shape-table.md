# Shape table: which view fits which raw work

Read this page when you select the body of the artifact.

Do not pour text into cards. Select the shape from what the recipient must do.

| Raw work | Shape | Core components |
|---|---|---|
| Report, metrics, analysis | **Dashboard** | KPI tiles with change and direction, one chart for each question, filter or tab for each segment, "what changed and why" notes |
| Plan, roadmap, project | **One-page plan** | Timeline or phases, owner and date on each item, status chips, risks, the decision you need |
| Decision memo, options, vendor selection | **Option comparison** | Options side by side on the same criteria, the recommendation marked, trade-offs, "what must be true" |
| Meeting notes, call transcript | **Decision and action board** | Decisions made, actions (owner + date, filter by owner, check boxes), risks and open questions. Discussion detail goes to a fold in layer 3 |
| Research, market or competitor study | **Claim and evidence cards** | Each claim as one sentence, its confidence, and its evidence in a fold. Confidence is a neutral tag: Strong (a number, or two or more independent sources), Medium (one source), Weak (no evidence in the source) |
| Code change, architecture, system design | **What-moved diagram** | Before and after as two columns of steps (`.cols` + `.steps`), the changed steps marked, list of changes by impact, risk, how to test, what changes for the users |
| Process, SOP, onboarding, how-to | **Stepper or checklist** | One action for each step, check boxes, warnings before the step they apply to |
| Proposal, contract, pricing | **Terms summary** | Who gives what, price, dates, obligations, exits, non-standard terms marked |
| Status update, weekly or board update | **Scorecard** | Green/yellow/red for each goal, changes since the last update, the help you need |
| Pipeline, account, customer review | **Account board** | One row for each account: stage, value, next step, owner, risk. Sort and filter |

If two shapes fit, the ask decides: a decision gets a comparison, a follow-up gets a board, a number question gets a dashboard. A long input can use tabs (a maximum of four), with one shape for each tab. The first tab is the one that serves the ask. For example, a quarterly report that needs a budget decision opens on the option comparison, and the dashboard is the second tab.

Interaction must do work. Use it to hide depth (folds, tabs), to let the reader ask a question of the data (filter, sort, toggle), or to let the reader act (check box, copy button). Do not add interaction for decoration.
